# 架构设计

状态：初始设计，未实现、未测量、未部署。

## 服务与控制台解耦

浏览器访问控制台 API，由 API 内的适配模块访问实际服务。DNS、Mihomo、Sub-Store 和定时更新任务各自运行；它们不依赖控制台进程。

后端使用 Go，嵌入构建好的 Preact 静态资源。Node 不作为控制台的运行依赖；Sub-Store 的运行依赖单独管理。前端不直接持有上游服务凭据。

基础 DNS 返回真实 IP，其上游可独立访问，不依赖 Mihomo、Sub-Store 或订阅更新。透明代理失效恢复由部署侧管理，不由浏览器或控制台健康探测驱动。

## 插件接口

初版插件随程序构建，通过显式注册表装配，通过配置启用；前端详情页按需加载。暂不支持运行时下载代码或动态脚本。

每个插件声明：

- 描述：ID、接口版本、名称、能力。
- 采集：状态、摘要、时间戳、有效期限和诊断信息。
- 操作：明确的操作 ID、参数约束、授权要求和执行结果。
- 展示：卡片、详情页面和外部服务入口。

能力可以仅提供入口，也可以包含状态或操作。插件之间不直接调用；认证、缓存、调度和日志属于公共核心。接口版本不兼容应在启动时报告。

启用与展示分别配置。禁用插件不注册操作或启动采集；隐藏卡片不会自动停止后台监测。服务故障时保留卡片并显示错误。状态统一为正常、降级、故障、未知，过期数据不能继续显示正常。

初版不宣称同进程插件具备安全隔离。采集采用超时、有限并发和错误边界；未来如支持不受信任插件，使用独立进程和版本化协议。

## 状态采集与展示

- 系统指标约每 5 秒采集，服务探测约每 15–30 秒；具体周期可配置。
- 服务状态区分 systemd 运行状态、API 可用性和实际功能探测。
- 所有浏览器共享采集结果，访问页面不会重复启动整套探测。
- SSE 推送更新，限制连接数和缓冲区，慢客户端不能阻塞采集。
- 内存历史固定容量，首版不引入数据库，日志交给 journald。
- 前端隐藏时暂停高频渲染；所有静态资源本地提供。

## 管理操作

控制台默认普通用户运行。特权操作经部署侧授权，仅允许明确的服务和动作，不接受任意命令、服务名或路径。

浏览器使用登录会话。修改请求需要认证、权限检查和 CSRF 防护。上游凭据只由后端读取，不通过 URL、日志或状态摘要泄露。服务入口与反向代理需显式配置，不开放任意目标代理。

## 订阅更新

systemd 定时任务和 WebUI 手动操作调用同一更新入口。Sub-Store 负责订阅转换；更新器负责超时、并发互斥、候选配置校验、原子替换及失败恢复。

只更新允许的节点数据，保护部署侧维护的 DNS、监听和路由设置。失败保留最后可用数据，不把更新成功等同于代理出口可用。展示最近尝试、最近成功和错误原因。

应用数据由对应服务管理；只在缺失时初始化，启动不能覆盖用户修改。迁移前备份；NixOS 回滚不能替代数据回滚。

## 性能预算

以下是待验证的目标，不是已测量结果：

| 指标 | 初步预算 |
| --- | --- |
| 后端常驻 RSS | ≤ 30 MiB，不含其他服务 |
| 空闲平均 CPU | < 1%，测量时注明 CPU 归一化方式 |
| 首页压缩 JS + CSS | ≤ 150 KiB，不含独立 Dashboard |

验收应记录硬件、插件组合、采样周期、并发浏览器数和测量方法。功能测试覆盖禁用插件、超时、缓存过期、慢客户端、上游断开和操作授权。架构兼容性至少覆盖 aarch64-linux 与 x86_64-linux。

## 交付边界

控制台仓库维护应用与通用插件。部署仓库固定引用应用版本，并管理独立的 DNS、Mihomo、Sub-Store、更新任务与服务授权。硬件 BSP、镜像和网络角色不进入控制台核心。
