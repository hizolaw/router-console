# 架构设计

状态：v0.1 只读状态与可选规则管理已实现；性能与构建验证记录见 [验证记录](verification.md)。2026-10-25 已在 R4S 上通过在线 switch 和运行验证，未做重启启动验收。

## 分层与所有权

```text
Preact 静态界面
       ↓ 同源只读 API
Axum：认证、静态资源、状态序列化
       ↓ 共享有界缓存
采集调度：最多 4 个并发、4 秒超时、失败退避
       ↓ Collector trait
system / dns / http / link
       ↓
/proc、指定 DNS 服务器、已配置的 HTTP 服务
```

Rust 编译时嵌入构建好的静态前端，Node 只参与开发和构建。运行时不用数据库，缓存只保留每个插件最新结果。静态资源使用本地字体和图标，不依赖互联网 CDN。

控制台不管理 DNS、Mihomo、Sub-Store 或订阅任务的生命周期。它们应由 NixOS 独立服务管理；网络恢复不依赖控制台健康探测。

## 当前插件接口

配置在 `config.rs` 定义，通用状态在 `model.rs` 定义，插件通过 `plugins::build` 显式注册。每个采集器实现异步 `Collector` trait，返回健康状态、摘要和指标。

- `system`：采集 CPU、内存、负载、运行时间、合计接口流量和可选温度。
- `http`：只检查固定配置地址的 HTTP 状态，不消费响应正文，不跟随重定向。
- `subscription`：异步读取受信任更新器提供的本地脱敏 JSON，读取上限 64 KiB；不下载订阅、不执行更新、不管理服务。仅消费最近尝试状态和已脱敏错误，历史成功不掩盖最新失败。文件路径不返回浏览器。
- `dns`：通过直连 UDP socket 向固定 DNS 地址发送 A 查询，验证响应 ID、问题、状态和关联的 A/CNAME 记录。
- `link`：纯入口，健康始终为“未知”，不计入功能探测正常数。

`enabled` 与 `visible` 独立。禁用不会构造采集器或访问服务；隐藏只影响首页展示。故障卡片保持可见。已启用插件按 ID 排序，最多 32 个配置项。前后端都检查过期状态，旧成功不能一直显示正常。

当前前端共用通用卡片，不提供自定义详情组件。新增通用 HTTP 或入口插件只需要配置。新增特殊采集器需要改 Rust 注册表并重新构建。

## 调度与故障边界

每个插件有独立采集任务，所有任务共用 4 个探测许可。超时取消当前异步探测，随后释放许可。失败以 2、4、8 倍周期退避，最大延迟为 `max(300, 原周期)` 秒；成功后恢复原周期。正常停机取消所有任务。

同进程插件不具备安全隔离；若插件 panic，该任务的缓存最终过期并显示未知。固定 `/proc` 和温度小文件的读取为同步读取，其他网络探测使用异步 I/O。未来第三方插件如需独立安装，采用进程外版本化协议，不使用 Rust 动态库 ABI。

所有浏览器共享采集结果，前端使用非重叠、带超时的轮询，页面隐藏后停止发起新轮询，重新可见时立即刷新。当前没有 SSE、长期历史数据或持久化数据库。

## 认证和权限

仅 loopback 监听可以不配置令牌，并验证 Host 以阻止浏览器 DNS rebinding。令牌模式的非 loopback 监听强制要求至少 24 字节令牌。服务端保存令牌摘要，比较使用常量时间操作。令牌模式中前端仅在内存保存令牌，不写入 URL、cookie 或 localStorage。

系统账户模式由非特权 Web 进程通过受限 Unix socket 调用独立 root PAM helper，仅允许部署侧指定的本地账户；helper 动态加载宿主 PAM 并执行 authenticate/account，不监听 TCP。登录并发最多 2 个、每分钟最多 8 次失败，全局计数有界；密码长度和请求正文有界。会话随机 256 bit，服务端只存哈希与用户名/过期时间，最多 128 个。登录与退出检查同源请求，使用 HttpOnly/SameSite=Strict cookie；前端不持久化密码。helper 故障关闭新登录，不切回令牌，不影响网络服务。

所有状态 API 都经过认证（配置令牌或系统账户时），无跨域授权，默认不提供服务配置修改；可选 Mihomo 规则插件的写请求另行校验同源并显式调用受限 worker。浏览器跨站 fetch 被拒绝。CSP 禁止第三方脚本、嵌入及任意连接。静态壳不含服务数据；状态 API 返回 `no-store`。

HTTP 插件可以从环境读取自己的 Bearer 凭据，不暴露探测 URL 或凭据到状态 API。管理入口 `url` 会返回浏览器，静态配置不得包含秘密。可选 `url_env` 从运行时环境读取完整入口（优先于静态地址），仅经认证状态 API 返回，以支持部署侧的一键连接。缺失或非法值隐藏入口，不影响探测；仅允许有界的 HTTP(S) URL，拒绝 userinfo 和控制字符。入口可能包含服务凭据，前端不额外持久化入口，API 禁止缓存；外部服务自身的令牌保存行为由其实现管理。没有任意命令执行、通用反向代理或特权操作。

令牌认证不提供传输加密，远程部署应使用可信管理网络、HTTPS 或隧道。应用默认普通用户运行。

## 后续接口

以下为计划，尚未实现：

- systemd 服务状态适配与明确的服务操作授权。
- Mihomo 进程、控制接口、代理出口的独立探测与专用详情。
- Sub-Store 更新记录、受保护的手动触发操作。
- 前端专用插件组件和接口版本协商。
Nix 打包与 NixOS 模块已提供，位于 `nix/`。宿主系统负责组合实际服务与地址；模块默认使用独立锁定的应用工具链。

订阅更新器归部署侧管理，定时任务与未来 WebUI 操作应调用同一入口。转换、候选配置校验、原子替换、失败恢复、数据迁移备份不应在浏览器中实现。基础 DNS 应返回真实 IP、独立访问上游，避免依赖代理。

## 性能目标与验收

初步目标：后端 RSS ≤ 30 MiB、空闲平均 CPU < 1%、首页压缩 JS + CSS ≤ 150 KiB。不把设计预算当成实测结果。

测量需注明硬件、插件数量、采集周期和浏览器并发数。验证需区分：代码测试、构建、普通 Linux 运行、R4S 实机启动。x86_64 和 ARM64 CI 构建不代表已验证板级部署。


## 可选 Mihomo 规则管理

`mihomo_rules` 插件按需展示轻量原生编辑器，结构化输入和原始文本操作同一份规则。GET/PUT `/api/plugins/{id}/rules` 与 POST `/api/plugins/{id}/rules/reload` 使用现有认证，写入要求同源。仅允许配置中启用的插件连接固定 Unix socket；RPC 限 512 KiB、45 秒、一个并发，不提供任意目标转发。

实际下载、候选验证、版本冲突、原子保存及回滚由部署侧独立 worker 实现；Web 不获得 root 或 Mihomo 的网络管理权限，也不负责启动/停止代理。探测调度不调用该管理进程；未启用插件时没有编辑入口。
